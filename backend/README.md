# Career Navigator — AI Backend

Backend AI-модуля проекта «Карьерный Навигатор».

AI-модуль отвечает за работу ИИ-ассистента, который:

- общается с пользователем;
- учитывает историю диалога;
- учитывает текущий сценарий карьерной навигации;
- учитывает текущий этап прохождения;
- формирует профориентационные ответы и рекомендации.

На текущем этапе AI работает через облачный API-сервис Groq
с использованием модели `openai/gpt-oss-20b`.

FastAPI выступает промежуточным backend-сервисом между основным
сервером приложения и AI-моделью.

# 1. Архитектура

Текущая архитектура AI-модуля:

React Frontend
       |
       | HTTP
       v
Node.js Backend
       |
       | HTTP POST
       v
FastAPI AI Backend
       |
       | HTTPS
       v
Groq API
       |
       v
GPT-OSS 20B

FastAPI отвечает за работу с ИИ:

- принимает запрос от Node.js;
- формирует системный prompt;
- загружает необходимые сценарии;
- передаёт историю диалога;
- отправляет запрос в Groq API;
- получает ответ AI-модели;
- возвращает ответ Node.js.

Node.js отвечает за основную серверную логику приложения,
авторизацию и работу с базой данных PostgreSQL.

Frontend не обращается к Groq API напрямую.

API-ключ Groq хранится только на backend и не передаётся
в браузер.

# 2. Преимущества архитектуры

Использование FastAPI в качестве отдельного AI backend позволяет:

- изменять AI-модель без изменения frontend;
- изменять AI-провайдера без изменения frontend;
- централизованно хранить API-ключ;
- добавлять новые сценарии общения;
- учитывать историю диалога;
- подключать дополнительные AI-функции;
- отделить AI-логику от основной серверной логики;
- использовать единую AI-инфраструктуру для всех пользователей.

# 7. Настройка API Groq

Для работы AI необходимо получить API-ключ Groq.

API-ключ хранится в файле:
    backend/.env

Пример содержимого:
    GROQ_API_KEY=YOUR_KEY
    GROQ_MODEL=openai/gpt-oss-20b
    GROQ_URL=https://api.groq.com/openai/v1/chat/completions

важно:

API-ключ нельзя помещать:

- в React;
- во frontend-код;
- в `.jsx` файлы;
- в публичные переменные Vite;
- непосредственно в исходный код.

Файл `.env` не должен попадать в Git.

# 8. Переменные окружения

Используются следующие переменные:
    GROQ_API_KEY

API-ключ для доступа к Groq API.
    GROQ_MODEL

Название используемой AI-модели.

Текущая модель:
    openai/gpt-oss-20b

    GROQ_URL

Адрес API Groq:
    https://api.groq.com/openai/v1/chat/completions


# 9. Prompts

Системные инструкции AI находятся в папке:
    backend/app/prompts/

Основные файлы:
    base.txt
    scenario_a.txt
    scenario_b.txt
    scenario_c.txt
    reflectionn.txt


`base.txt` содержит основные правила поведения
ИИ-ассистента.

Файлы `scenario_a.txt`, `scenario_b.txt` и `scenario_c.txt`
содержат инструкции для различных сценариев карьерной навигации.

FastAPI автоматически загружает необходимые prompt-файлы
в зависимости от переданного сценария.

# 10. Основной AI-сервис

Основная логика взаимодействия с AI находится в:
    backend/app/services/ai_service.py

Сервис выполняет следующие действия:

1. Загружает API-ключ Groq.
2. Загружает системный prompt.
3. Загружает prompt текущего сценария.
4. Учитывает текущий этап карьерной навигации.
5. Формирует историю сообщений.
6. Добавляет новое сообщение пользователя.
7. Отправляет запрос в Groq API.
8. Получает ответ модели.
9. Возвращает текст ответа FastAPI.

# 11. API FastAPI

Основной endpoint:
    POST /api/assistant/chat

Запрос имеет следующий формат:
    {
        "message": "Я люблю программировать и создавать сайты",
        "history": [],
        "scenario": "A",
        "stage": "interests"
    }

Параметры:
`message`
Текущее сообщение пользователя.
`history`
История предыдущих сообщений диалога.
`scenario`
Текущий сценарий карьерной навигации.

По умолчанию:
    A

`stage`

Текущий этап прохождения.

По умолчанию:
    interests

# 12. Ответ API

FastAPI возвращает ответ следующего вида:

    {
        "answer": "Это интересное направление...",
        "scenario": "A",
        "stage": "interests"
    }


Поле `answer` содержит ответ AI-модели.


# 13. Запуск FastAPI

Перед запуском необходимо:

1. Перейти в папку `backend`.
2. Активировать виртуальное окружение.
3. Проверить наличие файла `.env`.
4. Проверить наличие `GROQ_API_KEY`.

Активировать окружение:
    .\venv\Scripts\Activate.ps1

Запустить FastAPI:
    uvicorn app.main:app --reload

После запуска backend будет доступен по адресу:
    http://localhost:8000

или:
    http://127.0.0.1:8000

# 17. Работа с историей диалога

AI получает историю предыдущих сообщений.

Пример:

    {
        "message": "Мне нравится программирование",
        "history": [
            {
                "role": "user",
                "content": "Я люблю компьютеры"
            },
            {
                "role": "assistant",
                "content": "Расскажи, что именно тебе нравится..."
            }
        ],
        "scenario": "A",
        "stage": "interests"
    }


История используется для того, чтобы AI учитывал
предыдущий контекст разговора.


# 18. Сценарии

AI поддерживает несколько сценариев карьерной навигации.

Используемый сценарий передаётся в запросе:
    scenario

Например:
    A
    B
    C

Для каждого сценария FastAPI загружает соответствующий
prompt-файл.

# 19. Этапы карьерной навигации

Текущий этап передаётся в поле:
    stage

Например:
    interests

Этап используется AI для понимания текущей стадии
взаимодействия с пользователем.

# 20. Обработка ошибок

FastAPI обрабатывает основные ошибки взаимодействия
с Groq API.

Возможные ошибки:

- отсутствует API-ключ;
- ошибка подключения к Groq;
- превышен лимит API;
- ошибка авторизации API-ключа;
- превышено время ожидания ответа;
- Groq вернул некорректный ответ;
- AI вернул пустой ответ.

При возникновении ошибки FastAPI возвращает HTTP-ошибку
с описанием проблемы.

# 21. Модель AI

Модель используется через:

# 22. Итог

Текущая версия AI Backend работает по схеме:

    React
       ↓
    Node.js
       ↓
    FastAPI
       ↓
    Groq API
       ↓
    GPT-OSS 20B


FastAPI является отдельным AI-сервисом проекта.

Основная серверная логика, авторизация и работа
с PostgreSQL находятся в Node.js.

Локальный запуск AI-модели через Ollama больше
не требуется.
